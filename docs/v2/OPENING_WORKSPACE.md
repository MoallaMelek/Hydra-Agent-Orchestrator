# Opening workspace correction — 17 October 2026

The owner reported that the installed alpha.1 still looked the same. That report was correct: the successful installation included reliability/updater changes and task representations, but retained the incumbent opening shell. A version increment was not evidence of a substantial visual redesign.

## Direction

Structural alternatives considered: a launcher-led opening screen; a focused operation beside project launch controls; a dense cross-project execution ledger. Only the focused operation direction was implemented/rendered in this pass. It gives an idle installation meaningful saved work to inspect, while preserving genuine live slots and task concurrency when agents run. No invented activity fills an empty board.

The shared frame retains Hydra's branching mark and semantic themes, with a larger wordmark, clear current-route bar, quieter project navigation and consistent page hierarchy. The opening desk places the selected real task, operation rows or authoritative answer preview beside project launch controls. Selection prioritizes human decisions, then active tasks, then history; the owner can choose another task. A finished run is labelled execution finished, not verification passed. Inferred stage segments carry an explicit inferred label; missing history is no record, not an invented unstarted operation. Offline snapshots are labelled as such.

Initial snapshot loading is distinct from an empty installation. A remote client with no projects is directed to desktop setup. Failed operation detail loading offers an unavailable state and task-opening recovery. Unsent drafts, task identity, routing, approvals and engine decisions were not reimplemented. Preview text and candidate lists are bounded. No library, animation loop or timer was added; idle views do not subscribe to the live clock.
